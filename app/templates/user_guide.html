User Guide

Everything you need to use the Document Server — step by step.

What is this system?

The Related Document Server keeps all your scanned student documents in one place. When you add a document, the system reads it automatically and pulls out the details that matter for that kind of document (things like student name, course, ID number and date). You can then search for any document in seconds, and quickly check anything the system wasn't sure about.

The kinds of document it handles are fully configurable. Right now it's set up for Certificates and POEs (Grade Books) — but an administrator can add a brand-new document type at any time, with its own fields. See Add your own document types.

You don't need any technical knowledge. This guide walks you through each task with pictures. Use the quick links below to jump to what you need.

🧭 Finding your way around

Along the top of every page is the menu. These are the only places you'll ever need:

  • Dashboard

    The home page. See recent documents, how many need review, and add new documents.

  • Search

    Find any document by student, course, ID number, or date.

  • Review Queue

    The list of documents the system wasn't fully sure about, waiting for you to check.

  • Settings

    For administrators — create and manage document types and set up the automatic reader. See Add your own document types.

📤 Upload one document

The quickest way to add a single document:

  1. Go to the Dashboard

    Click Dashboard in the top menu.

  2. Scroll down to “Upload Document”
  3. Choose the document type

    Pick the type from the drop-down. It lists whatever types your organisation has set up (right now, Certificates and POEs — but there may be more).

  4. Add your file

    Drag the file onto the box, or click the box to browse your computer. PDF, PNG, JPG and TIFF files all work.

  5. Wait a moment

    The system reads the document and opens its details automatically. That's it — it's saved.

💡

After uploading, you'll land on the document's details page. If everything looks right, you're done. If a box is empty or wrong, just type the correct value and click Save Changes.

🗂️ Upload many at once (Bulk Upload)

Have a whole stack to add? Bulk Upload handles them all — one at a time so nothing gets missed.

  1. Go to the Dashboard

    Scroll down to the Bulk Upload section (below the single upload).

  2. Select all your files

    Drag several files onto the box, or click it and hold Ctrl (or Shift) to pick many. Different document types can be mixed together — the system works out the type of each one for you.

  3. Watch the progress

    Each file moves through the steps: Uploading → Identify → OCR Reading → AI Reading → Done. They process one after another.

  4. Check the results

    Each file ends with a green Approved or an orange Needs Review label. Click a label to open that document.

💡

Leave the page open until every file shows a result. Anything marked Needs Review will also appear in the Review Queue for you to fix later.

📝 Check & fix documents (Review Queue)

Sometimes the system can't read a field clearly — for example, handwriting or a missing ID number. Those documents wait in the Review Queue so you can quickly put them right. Nothing is lost; they're just held for a human to confirm.

  1. Open the Review Queue

    Click Review Queue in the top menu. Each row shows what's missing in the Reason column.

  2. Open a document

    Click the Review button on the right of the row.

  3. Compare with the scan

    The original scan is shown on the left. Read the details from it and fill in or correct the boxes on the right. Fields marked with a * are required.

  4. Save

    Click Save Changes. Once all required fields are filled, the document leaves the queue automatically and is filed away.

⚠️

The Delete Document button removes a document permanently and can't be undone. Only use it if a file was uploaded by mistake.

🔍 Find a document

The Search page finds any document already in the system.

  1. Click Search in the top menu
  2. Type what you're looking for

    Use the big search box for anything — a name, a course, or an ID number. Or use the boxes below to search a specific field or a date range.

  3. Open a result

    Click View on any row to open that document.

🏷️ What the labels mean

You'll see these small coloured labels next to documents. Here's what each one means:

Complete Complete / Approved — all required details were found. Nothing for you to do.
Needs Review Needs Review — a detail is missing or unclear. Open it, check it, and Save.
⚠ AI error AI error — the automatic reader had a problem (for example, it couldn't connect). The document is safe — just fill the details in by hand. If this keeps happening, tell your administrator.

On a document's details page you may also see “Extraction: Rules only” or “Rules + AI”. This simply tells you whether the system needed its smart AI reader for that document. It doesn't change anything you need to do.

🧩 Add your own document types

The system is not limited to Certificates and POEs — those are just the two types set up today. Whenever you start handling a new kind of paperwork (a report card, an ID copy, an attendance register — anything), an administrator can create a new document type for it, with its own set of fields. This is done on the Settings page.

On Settings, every existing type is shown as a card listing its fields, with Edit and Delete buttons and an + Add Type button at the top.

Create a new type — step by step

  1. Open Settings and click “+ Add Type”

    Under Document Types, click the + Add Type button. An editor opens.

  2. Give the type a name

    Type a Type name, e.g. “Report Card”. The Key next to it fills in on its own — it's a short internal id you don't need to worry about (it can't be changed later).

  3. Set how many pages to read

    Max pages is how many pages the system reads from each document. Use 1 for a single-page document like a certificate, or a few more for a booklet. Keeping it small keeps things fast.

  4. Add the fields it should capture

    Add existing field — pick a standard field (Student Name, Course, Student ID, Date…) from the drop-down and click Add.

    Add custom field — for something new, type a field name (e.g. “Term”), choose what kind of value it holds (text, number, date, or ID), and click Add.

  5. Mark each field required or optional

    For every field, tick required if a document can't be filed without it, and visible to show it on the form. (Required fields are what decides whether a document needs review.)

  6. Save

    Click Save. The new type is ready straight away — it appears in the upload drop-down, and its fields show on the review form.

💡

You can Edit a type later to add or remove fields, or Delete a type you no longer use. If any documents still use a type, the system warns you before deleting it.

⚠️

Document types are shared by everyone. If you're not sure whether to change one, ask your administrator first.

⚙️ The automatic reader (for administrators)

The system reads most documents on its own. For harder ones — like handwriting — it can call on a smarter AI reader. This is optional and is set up once by an administrator, in the AI Extraction section of the Settings page (shown above).

  1. Turn it on

    Tick Enable AI extraction.

  2. Enter the connection details

    Choose the Provider, enter the Model name and the API Key (and a Base URL if you're using an in-house reader).

  3. Test it

    Click Test Connection. A green message confirms it's working; a red one explains what's wrong.

  4. Save

    Click Save AI Settings.

⚠️

These settings affect everyone. If the AI reader isn't set up, documents that need it simply go to the Review Queue to be filled in by hand — nothing is lost.

🤖 Connect an AI assistant (MCP)

You can connect an AI assistant — like Claude — straight to the Document Server, so you can just ask it to find, read, add and tidy up documents for you in plain language. Behind the scenes this uses an open standard called MCP (Model Context Protocol). You don't install anything on the server — you point your assistant at one web address and it can do the rest.

What it can do for you

  • Find & read

    Search documents, open a full record, and even look at the actual scan.

  • Add documents

    Upload a single file or a whole batch — the assistant sends them through the same automatic reader as the website.

  • Work the review queue

    List what needs review and fill in or correct the details, which files the document away.

  • Check the setup

    See the document types and whether the automatic reader is connected.

💡

For your safety there is no “delete” action over this connection — the assistant can add and correct documents, but it can't remove them.

What you need

  • An MCP-capable app

    e.g. Claude Code, Claude Desktop, or Cursor.

  • To be on the same network

    Your computer must be able to reach the server (the office network / VPN).

    A shared password-like key. It's already filled into the setup commands below — just copy them.

Connection details

Server URL
{{ mcp_url or 'http://192.168.88.25:8000/mcp' }}
Transport
HTTP (streamable)
Auth header
Authorization: Bearer {{ mcp_token or '' }}

Set it up in Claude Code

Run this one command (replace <TOKEN> with your token):

Terminal — Claude Code 
claude mcp add --transport http related-documents \
  {{ mcp_url or 'http://192.168.88.25:8000/mcp' }} \
  --header "Authorization: Bearer {{ mcp_token or '' }}"

Set it up in Claude Desktop (or other apps)

Add this to your app's MCP configuration file (in Claude Desktop: Settings → Developer → Edit Config). It uses a small helper, mcp-remote, to reach the server:

claude_desktop_config.json 
{
  "mcpServers": {
    "related-documents": {
      "command": "npx",
      "args": [
        "-y", "mcp-remote",
        "{{ mcp_url or 'http://192.168.88.25:8000/mcp' }}",
        "--header", "Authorization: Bearer {{ mcp_token or '' }}"
      ]
    }
  }
}

Restart the app afterwards. The tools then appear under related-documents.

…or just tell your assistant

If your assistant can set up its own tools, you can simply paste it this:

Paste to your AI assistant 
Please connect to an MCP server over HTTP.
Name: related-documents
URL: {{ mcp_url or 'http://192.168.88.25:8000/mcp' }}
Header: Authorization: Bearer {{ mcp_token or '' }}
Then run the "server_health" tool and tell me if it's reachable.

Check it worked

Ask your assistant to “run server_health”. It should reply that the server is reachable. Then try “search for documents for student … ” — if it lists results, you're connected.

⚠️

The token is like a password: anyone who has it and can reach the server can read and change documents. Get it from your administrator, keep it to yourself, and don't post it outside the organisation. If it's ever exposed, an administrator can issue a new one.

💬 Need help?

If something doesn't look right, don't worry — nothing you do here can lose a document. The safest steps are always: open the document, compare it with the scan on the left, correct the boxes, and click Save Changes.

If a document keeps showing an AI error, or a page won't load, contact your system administrator.
